# Test run — Realtek RTL8822CS, 2026-08-15

Full conversion of a second CCPA adapter from Carlinkit firmware to OCBM-default, done over the
USB link with no UART wired. Recorded because the failures are as useful as the successes.

## Unit

| | |
|---|---|
| Product / serial | A15W CPC200-CCPA, `2024.01.19.1541f867` |
| Firmware / kernel | `2025.10.15.1127` / `3.14.52+g94d07bb` armv7l |
| WLAN/BT | Realtek **RTL8822CS**, SDIO `0xc822`, `/lib/firmware/rtlbt`, `rtk_hciattach` |
| Starting state | NCM CFW image installed, `/script/ncm_only`, reachable at `192.168.50.2` |
| UART | **not wired** — recovery was SPI programmer only |

Note `192.168.50.100` is normally the *host's* DHCP lease from the adapter's udhcpd, not the
adapter. The adapter is `.2`.

## 1. Carlinkit stack removed (`ncm_base_install.sh`)

| | before | after |
|---|---|---|
| rootfs free | 2.0 MB | **6.6 MB** |
| vendor projection binaries | 6 | 0 |
| processes | 20 | 7 |

Removed: `ARMadb-driver`, `ARMiPhoneIAP2`, `AppleCarPlay`, `ARMAndroidAuto`, `ARMHiCar`,
`ARMandroid_Mirror`, `AutomaticTest`, `boa` + its whole CGI web UI, `boxNetworkService`,
`colorLightDaemon`, `mdnsd`, `riddle_top`, `riddleBoxCfg`, `hwSecret`, `usbmuxd`, the vendor
`/script` set, `riddle.conf`/`RiddleBoxData`, and unreferenced `/usr/lib` + `/lib` libraries.

WLAN/BT untouched throughout: full `/lib/firmware/rtlbt` tree (driver tarball 917,595 B, BT
firmware, four baud configs), `rtk_hciattach`, `wl`, and all three bring-up scripts.

Both cold boots passed; NCM self-arms at **T+2s**, `early_console.sh` runs before `rcS`.

### Two bugs the run caught

* **`init_bluetooth_wifi.sh` was in the kill list**, inherited from the IW416 pass which
  replaced it with `wlan_on.sh`/`bt_on.sh`. This script installs no replacement, so removing it
  would have left the unit with no radio bring-up path at all. The `is_radio()` guard caught it;
  the list was then fixed so the intent is explicit.
* **The library-prune reference scan silently returned 0 sonames** — busybox's
  `tr -c '[:print:]'` yields nothing on this build — which made the guard vacuous and marked
  `libcrypto.so.1.1` removable. Now uses `strings` with fallbacks and **asserts** it found
  `libc` before trusting the result. An empty scan result must never read as innocence.

The audit also false-failed at first: it treated 10 dangling references as fatal when all were
`test -e` guarded — the multi-variant radio scripts name every chipset's helper
(`brcm_patchram_plus`, `hciattach`, `wpa_supplicant`) and a unit only ships its own, plus
`start_main_service.sh → ocbm_boot.sh`, which is exactly what should not exist yet. It now
classifies guarded vs unguarded and only fails on the latter.

## 2. Toolchain upgrades

### dropbear 2020.81 → 2026.91

Smoke-tested on port 2222 alongside the untouched daemon on 22 before replacing anything.

    SMOKE_OK, uid=0(root)
    dropbear_ed25519_host_key  83 B, 0600   ← generated by -R; the unit never had one
    server offers: ssh-ed25519,rsa-sha2-256 (was rsa-sha2-256,ssh-rsa,ssh-dss)

Cost ~280 KB. `/usr/sbin/{scp,dbclient,dropbearkey}` are now symlinks to the multi-call image.

Two attempts failed harmlessly first: staged as `dropbear.new`, the multi-call binary matched no
applet name and printed usage; and the smoke daemon, backgrounded over ssh, was SIGHUPed before
it could listen. The box was verifiably untouched after each (same md5, no `.pre`, nothing on
2222).

### busybox 1.32.1 → 1.37.0

    symlinks=358  old=350  new=402  working_today=315
    no regressions: every applet that works today survives
    restored (dangling today, provided by the new binary): 36

The 7 applets 1.37.0 lacks (`ar bash catv lzopcat msh uncompress unlzop`) are **already
dangling** on 1.32.1. Boot scripts were `sh -n`'d under the new binary before install. Reboot
clean.

**Finding: dropbear validates the login shell during authentication.** Pointing root's shell at
`/bin/rescue/sh` in `/etc/passwd` — the intended escape hatch — makes password auth fail
outright with "Permission denied" before any shell is exec'd. Substitute that works: a second
telnetd on port 24 where both the daemon and the shell come from the old binary
(`/bin/busybox.pre telnetd -F -l /bin/rescue/sh -p 24`), held open by a background ssh.

## 3. OCBM

Reversible trial, twice:

    accessory enumerated (0x1314:0x2d00)
    HELLO_ACK: box v1 caps=0x0000003f mode=0
    [ocbmd] CONSOLE attached (root)  →  uid=0(root)
    TTL expired with no /tmp/ocbm_keep — rebooting back to NCM

The first trial reported `device 1314 not found` while the box side was flawless
(`functions=accessory state=CONFIGURED pid=2d00`, `ocbmd running`). Cause was host-side: the
enumeration wait matched on *vendor* `0x1314`, which the NCM device also is, so it matched the
device being replaced and ran the handshake too early. Now waits for product `0x2d00`.

File transfer verified end to end over `CH_FILE`, md5-exact, and the final backup was pulled
over OCBM at **~200 Mbps**.

Then made default: `/script/ncm_only` removed, `::respawn:/script/run_ocbmd.sh` added to
inittab. That respawn line was a real gap — `ocbmd` exits on POLLHUP when a host disconnects,
and with no respawner and no NCM the first disconnect would have locked the box out entirely.

Final state, cold boot: accessory enumerated at ~25 s, `HELLO_ACK caps=0x3f`, root console,
busybox 1.37.0, 5.9 MB free, `OCBM healthy at 120s (ocbmd pid=71)` from the failover watchdog.

## 4. Failover watchdog

Detection validated in both directions on the box, with the action stubbed:

    absent daemon → MISS #1..#4 → WOULD FAIL OVER at 15s
    real ocbmd    → alive on every check, counter resets

The action (`touch /script/ncm_only; reboot`) has **not** been exercised from a genuine OCBM
failure — doing so means killing the daemon carrying the only console, and if the watchdog then
failed the unit would have neither channel. Accepted as best-effort recovery; the SPI image is
the guarantee.

## Transport notes

* **`scp`, never `scp -O`.** `-O` forces the legacy protocol, which needs an `scp` binary on the
  remote; the box has none. Plain `scp` uses SFTP mode and `/usr/libexec/sftp-server` is
  present. 440 KB in 0.5 s.
* **`ssh -n` inside a `while read` loop**, or ssh eats the loop's stdin and only the first item
  is processed.
* **Anything backgrounded over ssh/telnet dies of SIGHUP when the session closes.** This
  silently truncated `nc` transfers at 1 KB / 304 KB / 347 KB, and stopped dropbear from ever
  listening on its smoke-test port. `setsid` did not help. What works: run it in the foreground
  under a session the host script holds open in the background, then kill it.
